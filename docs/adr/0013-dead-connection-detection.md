# ADR-0013: 죽은 연결 감지는 수신 없음 제한 시간으로

- 상태: 승인 (2026-10-21)
- 보완: ADR-0007

## 맥락
EW11 전원이 끊기면 FIN이 오지 않아 TCP 연결이 반쯤 열린 채로 남는다. 이때 `read`는 영원히 기다리고 연결 상태는 계속 "연결됨"이라 엔티티가 `unavailable`이 되지 않는다.

## 결정
- Transport에 `idle_timeout`을 둔다. 그 시간 동안 1바이트도 받지 못하면 연결을 끊고 재연결(ADR-0007 백오프)한다.
- 값은 coordinator가 정한다: **Polling 주기 × 3** (기본 60초 → 180초).
- 연결 시도 제한 시간 `connect_timeout` 10초. 초과 시 실패한 시도로 센다.
- `on_data` 콜백 예외는 로그만 남기고 수신을 계속한다 (연결 문제가 아님).

## 검토한 대안
- TCP keepalive: 원인을 정확히 짚지만 OS별 소켓 옵션이 다르고, 죽은 상대를 자동 테스트로 재현할 수 없다.
- coordinator가 ACK 실패 시 재연결 요청: ACK 실패는 대개 버스 충돌이므로 ADR-0007과 충돌한다.

## 결과
- 현재 버스에는 Integration 외 Master가 없어(ADR-0012) 수신 바이트는 모두 Polling 응답이다. Boiler Controller만 침묵해도 재연결이 일어나지만, 그 시점엔 Room들이 이미 무응답으로 `unavailable`이므로 사용자에게 보이는 결과는 같다.
- Relay 등 다른 Master가 버스에 붙으면 수신이 잦아져 감지가 늦어질 수 있다 → 그때 재검토.
