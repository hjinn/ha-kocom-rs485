# Kocom RS485 프로토콜 (Thermo 범위)

참조 구현(`clipman/kocom.py`)의 동작에서 정리한 사실. 코드는 옮기지 않는다 (ADR-0011).
**[검증 필요]** 표시는 실기기 캡처(`docs/capture-guide.md`)로 확인해야 하는 항목.

## 물리 계층

- RS485, 9600 bps, 8N1. EW11이 TCP 서버로 노출 (기본 포트 8899).

## Packet (21바이트)

| 인덱스 | 길이 | 필드 | 값 |
|---|---|---|---|
| 0–1 | 2 | 헤더 | `aa 55` |
| 2–3 | 2 | 타입(상위 12비트) + seq(하위 4비트) | 타입 `30b`=send, `30d`=ack / seq `c`,`d`,`e`,`f` = 1~4번째 시도 |
| 4 | 1 | monitor | `00` (월패드) |
| 5–6 | 2 | 목적지 주소 | 장치 코드 + 서브 ID |
| 7–8 | 2 | 출발지 주소 | 장치 코드 + 서브 ID |
| 9 | 1 | 명령 | `00` state, `3a` query (`01` on, `02` off — Thermo에서는 미사용) |
| 10–17 | 8 | 값 | 장치별 |
| 18 | 1 | 체크섬 | 인덱스 2~17 바이트 합 mod 256 |
| 19–20 | 2 | 트레일러 | `0d 0d` |

예: `aa55 30bc 00 0044 0001 00 0300000000000000 35 0d0d` (원본 주석에 있던 실제 패킷, 체크섬 일치 확인됨)

## 주소

- 장치 코드: `01` Wallpad, `36` Thermo
- Thermo 서브 ID = Room: `00` livingroom, `01` bedroom, `02` room1, `03` room2
- Integration이 보내는 패킷의 출발지는 **Master 주소 `0100`** 이다. 현재 버스에는 실제 월패드가 없으므로 Integration이 유일한 Master다.
- Boiler Controller가 Thermo 주소 `3600`~`3603`에 응답한다.

## Thermo 값 (8바이트)

실기기 관측(2026-10-21, `captures/01`~`05`)과 실내 온도조절기 화면으로 확인:

| 바이트 0 | 바이트 1 | 바이트 2 | 온도조절기 표시 | 근거 |
|---|---|---|---|---|
| `11` | `00` | 설정 온도 | 난방 (설정 온도) | `01`: 조절기에서 24→23→24 조작 |
| `11` | `01` | `0a` (10) | 외출 | `01`: 조절기에서 외출 버튼 |
| `00` | `01` | `0a` (10) | **꺼짐** | `05`: `off` 명령 후 화면 확인 |

**해석 규칙**: 바이트 0이 `00`이면 꺼짐 (바이트 1·2 무시). `11`이면 바이트 1이 `01`일 때 외출, `00`일 때 난방.
→ 상태는 꺼짐 / 난방 / 외출 **세 가지 중 하나**다. "외출 플래그"를 독립된 불리언으로 읽으면 꺼진 방이 외출로 잘못 표시된다.

| 바이트 | 의미 |
|---|---|
| 0 | `11` 켜짐 / `00` 꺼짐. 보고에서 `01`은 관측되지 않음 (`off` 명령으로 `01`을 보내도 `00`으로 보고됨) |
| 1 | 켜짐일 때 `01` 외출, `00` 재실. 꺼짐일 때도 `01`로 보고됨 |
| 2 | 난방일 때 설정 온도 (℃). 외출·꺼짐일 때 `0a`(10) |
| 3 | 관측값 항상 `00` |
| 4 | 현재 온도 (℃). 관측값 25, 26 |
| 5–7 | 관측값 항상 `00` |

## 명령 (Integration → Thermo, cmd `00`)

| 동작 | 보낸 값 | Controller 보고 (확인됨) |
|---|---|---|
| 난방 켜기 + 설정 온도 T | `11 00 T 00 00 00 00 00` | `11 00 T 00 <현재> 00 00 00` — 외출 상태에서도 재실·난방으로 전환됨 |
| 난방 끄기 | `01 00 T 00 00 00 00 00` | `00 01 0a 00 <현재> 00 00 00` |
| 외출 | `11 01 0a 00 00 00 00 00` | `11 01 0a 00 <현재> 00 00 00` — 난방에서도 꺼짐에서도 전환됨, 30초 유지 (`07-away`) |
| 상태 조회 | cmd `3a`, 값 전부 `00` | 현재 상태 |

## 메시지 흐름 (확인됨)

```
 Integration(0100)                    Thermo(36xx, Controller)
   │ ① send  seq=c  cmd/값 ───────────→│
   │←────────── ② ack seq=c (같은 cmd/값 그대로 반사)   ≈125ms 후
   │←────────── ③ send seq=c cmd=00 값=현재 상태        ≈300ms 후 (①기준)
   │ ④ ack seq=c (③ 그대로 반사) ─────→│   ④가 없으면 ③을 seq d, e로 ≈300ms 간격 재송신 후 포기 (f는 보내지 않음)
```

- ② ACK는 `Packet.ack()` 규칙과 정확히 일치한다 (`02`~`05` 로그 전부).
- **참조 구현이 상태로 쓰던 "Wallpad → Thermo ack" 패킷은 실제 Master가 없으면 존재하지 않는다.** 상태는 ③에서 읽는다.
- ④는 `probe --ack`로 보냈을 때 재송신이 즉시 멈췄다 (`03`, `04`).
- 응답 시간은 매우 일정하다: ② 124~132ms, ③ 298~379ms (①기준, 13회 측정).

## 자발적 상태 보고 (확인됨)

Integration이 아무것도 보내지 않아도 **Room 상태가 바뀌면 Thermo가 ③과 같은 형식의 보고를 보낸다** (`01-passive`: 거실 설정 24→23→24→외출, 50초 동안 4회).
- 형식·재송신(c, d, e) 모두 ③과 동일. Master가 없으므로 아무도 ACK하지 않는다.
- 4개 Room 중 거실만 관측됨 (해당 시간에 바뀐 방이 거실뿐이었던 것으로 보임).
- **명령 되돌림 (원인 확인됨)**: Master가 ③ 보고에 ④ ACK를 보내지 않으면, Thermo가 c, d, e 재송신을 마친 뒤 **약 2.3초 후 명령 이전 상태로 되돌리고** 그 상태를 다시 보고한다 (`06-revert`).

  | 실험 | 원래 → 명령 | ④ ACK | 30초 관찰 결과 |
  |---|---|---|---|
  | 5-1 | 꺼짐 → 난방 24 | 없음 | 난방 24 보고 → 마지막 재송신 2.3초 뒤 **꺼짐으로 되돌아감** (`05`에서도 동일) |
  | 5-2 | 꺼짐 → 난방 24 | 보냄 | 난방 24 유지 |
  | 5-3 | 난방 24 → 난방 25 | 보냄 | 난방 25 유지 |

  → **명령은 ④ ACK까지 보내야 확정된다.** `05`의 외출 → 난방 24(ACK 없음)가 10초간 유지된 것은 관찰 시간이 짧았거나 되돌림 조건이 다른 것일 수 있으나, ACK를 보내면 문제가 없으므로 더 파고들지 않는다.
  - 온도조절기에서 직접 바꾼 값(`01-passive`, ACK 없음)은 되돌아가지 않았다. 되돌림은 Master가 보낸 명령에만 적용되는 것으로 보인다.

## 송신 절차

1. **쓰기 타이밍**: 마지막 바이트 수신 후 최소 30ms가 지난 뒤 쓴다. 연결 직후 아직 수신이 없으면 1초 대기. (관측: ③ 수신 후 35ms 뒤 보낸 ④가 정상 처리됨)
2. seq `c`로 송신한다.
3. **② ACK 대기**. 기대 ACK = `Packet.ack()`. 참조 구현은 1.3~1.5초를 기다렸으나 실측 응답은 ≈130ms다 (Integration은 0.5초).
   - ② **이전에** 온 같은 방의 Report는 결과로 쓰지 않는다 (상태 반영과 ACK는 한다). 이전 Report의 재송신일 수 있다. 참조 구현의 "ACK 전에 상태 응답이 오면 ACK로 간주" 규칙은 실기기에서 관측되지 않아 쓰지 않는다 (②는 항상 ③보다 먼저 왔다, 13회).
4. ACK가 없으면 seq `d` → `e` → `f`로 재송신한다. 4번 모두 실패하면 명령 실패.
5. **③ 상태 보고 대기**: 출발지 = 대상 Thermo, 목적지 = Master, 타입 send, cmd `00`. 받으면 즉시 **④ ACK** 를 보낸다. **④가 없으면 명령이 약 3초 뒤 되돌려진다.** 재송신(d, e)이 오면 그것에도 ACK한다.
6. 한 번에 하나의 요청만 진행한다 (직렬화).

## Polling

- Room마다 query(`3a`)를 순차 송신한다. 4개 Room 전부 응답함 (`04-scan`, 서브 ID `00`~`03`).
- 참조 구현은 Polling 주기 안에 감청으로 받은 보고가 있으면 query를 생략했다 (캐시). 버스 점유를 줄이므로 동일하게 적용한다.
